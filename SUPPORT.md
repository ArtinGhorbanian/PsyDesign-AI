# Support

Support is available only for authorized collaborators working in the private
repository. There is no supported public release, hosted service, commercial
offering, or service-level commitment.

## Where to ask

- Open a private repository issue for a reproducible defect, feature request,
  documentation problem, rights question, or commercial inquiry.
- Use GitHub Discussions, when enabled, for general usage, design, and process
  questions that do not need issue tracking.
- Follow `SECURITY.md` for suspected vulnerabilities.

Issues and Discussions are the only project support channels. Do not post
credentials, API keys, database contents, private prompts, personal data,
contracts, or other confidential material.

## What to include

Provide the affected commit, operating system and Python version, concise
reproduction steps, expected and observed behavior, and sanitized logs. A
minimal example is preferable to a database or complete report export.

## Scope and expectations

Support is best effort, with no guaranteed response or resolution time.
Requests may be closed when they cannot be reproduced, concern an unauthorized
deployment, require disclosure of sensitive data, or fall outside the current
private project scope.

Commercial or rights questions do not imply that a license is available or
that any participant has authority to offer one. Use the commercial inquiry
issue form to record the proposed scope without asserting clearance.
