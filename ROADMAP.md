# Private Project Roadmap

This roadmap is directional, not a promise of delivery, ownership, funding,
licensing, or public availability. Every phase remains subject to documented
authority, privacy review, security review, and the controlling release gate.

## Phase 0 — Resolve the release gate

- Establish a complete contributor and provenance register.
- Reconcile contribution, institutional, client, employer, and competition
  obligations using documentary evidence.
- Confirm authority for the project names and visual identity.
- Obtain an explicit license decision from the verified rights holder or
  holders without presuming exclusive ownership.
- Lock the full dependency graph and prepare a complete SBOM, license-text
  bundle, and private release manifest.

This phase blocks every public or commercial release decision.

## Phase 1 — Strengthen the private engineering baseline

- Keep lint, typing, test, dependency-audit, and static-security checks green.
- Expand tests around authorization boundaries, rate limiting, stored data,
  provider failures, export behavior, and multilingual/RTL paths.
- Define retention, deletion, backup, and secret-management practices before
  any shared deployment.
- Document threat models and review generated-content safety and privacy.

## Phase 2 — Validate product quality privately

- Test core brand-generation and persona workflows with authorized synthetic
  data.
- Measure accessibility, responsiveness, failure recovery, and performance.
- Review all user-facing claims, translations, exports, and generated examples.
- Define a reversible migration path for stored records and configuration.

## Phase 3 — Make a documented release decision

Only after Phase 0 is complete, authorized decision-makers may determine
whether the project remains private, receives a limited internal license, or
is prepared for another distribution model. Any decision requires a new legal,
security, privacy, dependency, asset, and operational review.

## Not currently planned or authorized

- a public repository, package, hosted demo, or portfolio publication;
- an open-source or commercial license;
- public branding or trademark claims;
- distribution of generated/user-provided records or excluded raster assets;
  or
- production availability or support commitments.

Propose roadmap changes through a private issue. Use GitHub Discussions, when
enabled, for non-sensitive planning questions.
